# 对话保存与会话日志

## 查看长回复

对话区有独立的垂直滚动条，输入框固定在底部。鼠标滚轮、拖动滚动条或键盘都可以查看历史内容。生成时如果向上滚动，页面会暂停自动跟随；点击“回到最新消息”继续跟随。代码块和宽表格可以横向滚动。

## 会话自动保存

每次发送前保存用户消息，流式生成期间每隔约 250 毫秒保存已收到的文本，完成、失败或停止时立即保存最终状态。刷新页面、关闭后重新打开浏览器或重启 Go 服务后，最近对话与当前会话自动恢复。

会话保存在当前浏览器的 localStorage，使用的键为 `hao-harness-conversations-v1`。请保持浏览器、协议、主机名和端口相同，例如始终使用 `http://127.0.0.1:8080/`。`localhost` 与 `127.0.0.1` 的浏览器存储相互独立；更换浏览器、清理站点数据或隐私窗口结束后，原来的存储不会自动迁移。

生成中关闭页面时，下次打开会标注“上次生成已中断”，保留最后已保存的文本。中断、停止或失败的助手消息不会作为完整回答发送到下一轮模型上下文。浏览器突发崩溃可能丢失最近约 250 毫秒尚未写入的片段。

右上角“导出对话”可下载所有会话的 JSON 备份，不包含上游凭证。浏览器存储不可用或空间不足时，输入框下方会显示保存失败，此时可以导出仍在内存中的对话。当前没有导入备份界面；导出的文件可以直接用编辑器查看。

## 一个会话一个日志文件

正常启动服务即可启用会话日志：

```powershell
go run ./cmd/server
```

在项目根目录运行时，默认保存位置为：

```text
C:\Users\16255\code\hao-agent-harness\logs\requests\
  session-<会话ID>.log
```

同一会话的所有请求都会追加到这个文件。点击“新建对话”会创建新的会话 ID，下一轮回复结束后生成新的日志文件。刷新页面或重启服务后，恢复的会话继续使用原 ID，追加到原文件。

**模型输出结束后才写文件。** 流式片段只在内存中合并，不逐条保存 SSE 事件；普通响应和流式响应最终都记录为一条完整回复。每轮追加一个缩进排版的 JSON 对象，对象之间用空行分隔，文件是 JSON 对象序列。

| 字段 | 用途 |
| --- | --- |
| `session_id`、`request_id` | 关联会话与该轮请求 |
| `request` | 完整本地请求：模型、system 指令、历史消息、新问题和可选参数 |
| `response` | 合并后的完整回答、结束原因、上游提供的 token 用量 |
| `started_at`、`finished_at`、`duration_ms` | 调用时间与耗时 |
| `status`、`outcome`、`error` | 最终结果，失败时附公开错误 |

请求失败或被取消时，在终止后只追加一条结果，包含已经收到的部分回复与错误状态。流式 HTTP 状态可能是 200，但业务失败，判断成功还应看 `outcome` 是否为 `success`。进程被强制终止时，尚未结束的这一轮不会写入服务端日志；已经完成的轮次保留。

终端 `chat_log_saved` 会显示会话 ID 和文件路径。目录已加入 Git 和 Docker 忽略列表，HTTP 请求头和供应商凭证均不写入日志。

这些文件记录的是本服务聊天接口的请求与最终回复，不包含 OAuth 令牌交换或供应商内部的全部原始 HTTP 流量。请求体读取成功后开始在内存中收集内容；请求体超限或会话 ID 无效等情况仅有终端元数据与错误。

旧版的请求目录与多文件日志不会自动删除；新请求采用上述单文件格式。

## 其他客户端如何关联会话

前端自动添加 `X-Session-ID` 请求头，无需手动设置。直接调用 API 时，在同一会话的每轮请求中传递相同的 `X-Session-ID`。

会话 ID 长度为 1～64 个字符，首字符为字母或数字，其余允许字母、数字、下划线和连字符。不能包含路径分隔符或点号。未传递时，服务会生成新的 ID，并通过响应头 `X-Session-ID` 返回；后续请求可复用这个值。`X-Request-ID` 只用于单次请求追踪，不用于关联会话。

## 自定义目录与查看文件

在 `configs/models.json` 中设置 `logging.chat_log_dir` 可更改目录；设置为空字符串可关闭会话日志，保留终端访问日志。文件变更会被校验并热加载。

查看最近更新的会话日志：

```powershell
$latestChatLog = Get-ChildItem .\logs\requests -File -Filter 'session-*.log' |
  Sort-Object LastWriteTime -Descending | Select-Object -First 1
Get-Content $latestChatLog.FullName -Raw
```

浏览器会话与服务端日志是两份独立保存的数据：浏览器负责继续对话，服务端文件负责查看和学习完整调用。浏览器仍在流式生成期间保存收到的内容；服务端日志等这一轮结束再写入。日志不会自动删除。启动时目录无法创建会直接报错，运行中磁盘写入失败会记录 `chat_log_failed`，聊天响应仍尽力完成。

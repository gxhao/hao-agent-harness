# 前端消息渲染

## 助手回复

助手回复由本地 `marked` 解析 Markdown，再由 `DOMPurify` 安全过滤，最后作为 DOM 节点插入消息容器。普通回复、历史记录与流式回复共用同一个渲染入口，因此格式和安全策略保持一致。流式片段先合并，再按动画帧刷新视图，避免每个 SSE 事件都重新排版。

Markdown 中混入未闭合的 HTML 标签时，HTML 解析器会将输入解析为 DOM 节点树；过滤后的内容再以节点片段写入页面，不会把未闭合标签带进工作台外层结构。如果解析过程遇到异常，页面会安全地按纯文本显示原回复，内容不会丢失。

用户消息、状态提示、等待动画、发送按钮与回答风格按钮均使用 DOM API 创建节点或设置 `textContent`。这样只需解析模型回复这一处 HTML 字符串，并可将其限定在 Markdown 解析与清理链路内。修改界面时不要把动态内容直接拼到 `innerHTML`。

链接只开放 `http`、`https` 和 `mailto` 地址，任务列表复选框只读。修改允许的 Markdown 标签、属性或链接规则时，要同时检查脚本、事件处理器、相对 URL、代码围栏和表格等输入。

前端代码位于 `internal/webui/static/assets/`；页面依赖通过 Go 静态资源白名单嵌入并提供。新增静态资源时，同时更新 `internal/webui/server.go` 的白名单。

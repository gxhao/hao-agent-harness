# 启动时自动加载 .env

## 目标与当前行为

此前服务仅通过 `os.Getenv` / `os.LookupEnv` 读取进程环境，即使项目根目录的 `.env` 已配置 `CLIENT_API_KEYS`，直接执行 `go run ./cmd/server` 仍可能报缺失。现已按确认方案在命令行入口自动加载 `.env`，然后沿用现有配置读取、校验及鉴权。

## 加载流程与优先级

1. 先解析命令行参数；帮助和非法参数不读取 `.env`。
2. 从当前工作目录读取唯一的 `.env`，不搜索父目录，不加载 `.env.local` 等文件。
3. 完整解析成功后，仅将进程环境中尚不存在的变量写入环境。已有环境变量优先，包括显式设置为空的变量；文件中重复的变量以最后一次声明为准。
4. 再分流：`--login` 使用加载后的凭证路径；普通启动执行现有 `config.Load()` 和配置校验。

因此登录和服务都能使用 `.env` 的 `OPENAI_CODEX_TOKEN_FILE`，但登录仍不要求客户端令牌或模型配置。相对路径继续相对于当前工作目录解析。变更 `.env` 后需重新启动进程；不引入热加载或自动修改文件。

## 文件格式与错误边界

- 使用标准库实现明确、有限的 dotenv 语法，不增加依赖：支持 `KEY=value`、可选 `export` 前缀、空行、整行注释和两端空白。
- 变量名必须符合 `[A-Za-z_][A-Za-z0-9_]*`；支持空值、单引号和双引号包裹的单行值。单引号内容保持原样，双引号支持 `\\`、`\"`、`\n`、`\r`、`\t` 转义。
- 未加引号的值中，行首或空白后的 `#` 表示注释；引号内的 `#` 保留。支持 CRLF 和文件开头的 UTF-8 BOM。
- 不执行 shell 命令，不展开 `$VAR` / `${VAR}`，不支持跨行值；未知双引号转义、未闭合引号、引号后非注释内容和非法赋值均报错。
- `.env` 不存在时正常继续，兼容只通过进程环境部署的方式；存在但不可读、超过 1 MiB 或格式错误时退出。完整解析前不注入变量，避免格式错误导致部分加载。
- 错误只包含文件名、行号和错误类别，不包含配置值或原始行。变量写入失败也终止启动。

## 修改范围与文档

- `internal/config/dotenv.go`：提供加载与解析函数；不让 `config.Load()` 隐式修改环境，保持配置包现有调用方式。
- `cmd/server/main.go`：在参数解析成功后、登录和服务分流前调用加载函数，复用结构化配置错误日志。
- `tests/config/dotenv_test.go`：通过公开的 `LoadDotEnv` 验证加载规则，不依赖私有解析函数；配置衔接测试位于 `tests/config/config_test.go`。
- `tests/cmd/server/login_test.go`：编译命令行程序，在隔离目录中检查参数、退出码和两种入口的调用顺序。原生产目录中的测试已迁移，未扩大生产接口。
- `README.md`、`.env.example`、`docs/openai-codex-auth-flow.md` 和 `docs/llm-http-server-design.md`：同步自动加载、优先级、支持格式和排错说明。

## 安全、兼容性与验证

`.env` 已被 `.gitignore` 忽略；保留现有文件内容，不读取或打印真实密钥作为测试输出。客户端令牌仍必填，上游密钥与客户端令牌仍各自独立。新增影响是启动命令会读取当前目录的 `.env`，且非法文件会阻止启动；系统环境可覆盖文件配置。

测试覆盖缺失文件、读取错误、大小限制、格式与引号、BOM/CRLF、空值、重复项、环境优先级和解析失败时不注入变量，并验证登录分支也加载配置、帮助分支不加载。运行 `gofmt`、`go test ./...`、`go vet ./...` 和 `go build ./cmd/server`，检查最终 diff 与文档一致。
